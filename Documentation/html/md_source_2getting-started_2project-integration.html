1. 推荐工程结构

YourApplication/
├── src/
├── ref/
│ └── hts.viewer/
│ └── win/
│ ├── include/
│ ├── lib/
│ └── bin/
└── CMakeLists.txt

这种组织方式的目标是让 Viewer SDK 作为明确的二进制依赖存在，而不是把 Viewer 源码混入业务工程。

2. Include

推荐只在需要 Viewer 的代码中包含：

#include <HtsViewerSdk.h>
HtsViewerSdk.h

3. Link

CMake 中应让业务 target 链接 Hts3dViewerSDK.lib 对应的 Imported Target 或链接库。

具体 target 名称以正式 SDK Package 的 CMake 配置为准。

如果当前工程尚未提供 find_package(Hts3dViewerSDK CONFIG)，也建议把 SDK 路径集中在项目顶层 CMake，不要在每个业务模块重复硬编码。

4. Runtime

构建后应确保 Viewer Runtime DLL 被部署到应用可搜索位置，例如应用 exe 同目录。

建议由 CMake 的 post-build 或 install 规则自动处理，而不是要求最终用户手动配置系统 PATH。

5. 业务数据转换层

建议业务项目建立一个明确的数据转换边界：

Business CAD / Mesh / Solver Data
│
│ convert
▼
Hts Viewer Public DTO
│
▼
HtsViewerSdk

转换代码属于业务应用，不属于 Viewer SDK。

6. 不要形成的依赖

业务代码不应依赖：

  • Viewer 内部头文件；
  • Viewer 内部 Manager；
  • Viewer 私有场景对象；
  • Viewer 的私有渲染实现；
  • Viewer 源码目录；
  • Demo 私有 Importer。

7. 多 Viewer

HtsViewerSettings 是 Per-Viewer 设置对象。业务系统如果创建多个 Viewer 实例，应分别维护和应用各自设置。

8. UI 集成

嵌入模式需要结合宿主窗口生命周期：

  • 初始化 Viewer；
  • 转发 Resize；
  • 转发输入事件；
  • 驱动 Frame；
  • 在窗口销毁时结束 Viewer 使用。

具体宿主平台代码请以对应正式 Sample 为准。

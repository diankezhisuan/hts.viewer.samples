大模型使用建议

本章只从**公开 API 使用方式**讨论大模型，不披露 Viewer 私有性能实现。

1. 保持业务 ID 稳定

对于长期存在的 Object / Mesh Part，保持：

  • objectId
  • bodyId
  • faceTag
  • edgeTag
  • vertexTag
  • meshId
  • partId

稳定。

不要仅因为某个对象颜色改变就为它生成新的 objectId。

2. 使用增量 API

局部对象变化：

upsertDisplayData(...)

Mesh Part 变化：

upsertMeshPart(...)

不要把：

clearScene();

作为普通属性修改和局部修改的默认操作。

3. 大 Mesh 使用 Part

把业务上可独立更新、显隐或选择的 Mesh 区域组织为稳定 partId。

Part 粒度应来自业务和更新需求，不需要为了猜测 Viewer 内部实现而人为模拟私有渲染分组。

4. 分阶段提交

当业务侧生成 Mesh 数据需要较长时间或数据量较大，可使用：

beginMeshUpdate()
appendMeshPart()
endMeshUpdate()

保证业务层先准备 staged 数据，再显式发布。

5. Frame

如果：

viewer.hasPendingFrameWork()

返回 true，应用程序仍应继续正常驱动 Frame。

不要阻塞 GUI 线程等待 Viewer 私有执行细节。

6. 不在 UI 线程进行重型 CAD 转换

Viewer 接口只接收已经准备好的 DTO。

业务应用可在合适的后台任务中准备纯业务数据，但：

  • Qt UI 更新；
  • Viewer API 调用的线程要求；

应遵循当前 SDK 与 Sample 的正式约定。

在没有公开线程安全声明的接口上，不要自行假定可以从任意工作线程并发调用。

7. 量化性能

具体最大模型规模、FPS、首帧时间和显存占用，应以当前 Release 的 Benchmark 为准。

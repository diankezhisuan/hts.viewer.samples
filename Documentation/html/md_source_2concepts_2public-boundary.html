SDK 公开边界

本章只描述 Hts Viewer SDK 对业务开发者公开的使用边界，不介绍 Viewer 私有架构。

1. 公开调用模型

Application
│
├─ CAD / Geometry
├─ Mesh / Solver
├─ UI / Interaction
└─ Business IDs
│
▼
Hts Viewer Public DTO
│
▼
HtsViewerSdk

业务程序负责准备公开数据，Viewer 负责执行公开接口所描述的显示与交互行为。

2. 公开内容

业务层可以依赖：

  • HtsViewerSdk
  • HtsViewerTypes
  • HtsDisplayData
  • HtsMeshData
  • HtsViewerSettings

3. 非公开内容

业务层不应依赖 Viewer 的：

  • 私有节点组织；
  • 私有渲染对象；
  • 内部 Manager；
  • 内部缓存；
  • 私有线程模型；
  • 内部 Shader；
  • 内部渲染阶段；
  • 内部合批、重建或调度策略。

这些内容不是 SDK 兼容性承诺的一部分。

4. 为什么要保持边界

只依赖公开 API 可以获得：

  • SDK 版本升级时更小的业务改动面；
  • Viewer 内部优化不影响业务代码；
  • CAD Kernel 与 Viewer 解耦；
  • OSG 与业务层解耦；
  • Demo Importer 与 SDK 解耦。

5. 商业产品文档原则

本手册会解释：

  • 一个接口解决什么业务问题；
  • 输入数据必须满足什么规则；
  • 调用顺序如何组织；
  • 常见错误如何避免。

本手册不会通过“架构介绍”披露实现 Viewer 性能与渲染效果所依赖的私有核心技术。

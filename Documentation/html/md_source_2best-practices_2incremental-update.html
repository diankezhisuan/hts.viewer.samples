1. 为什么使用 Upsert

Viewer 公开 API 提供 Upsert，业务层应该利用稳定身份表达“这个对象发生了变化”。

Display：

viewer.upsertDisplayData(data);

Mesh：

viewer.upsertMeshData(mesh);
viewer.upsertMeshPart(meshId, part);

Preview：

viewer.upsertPreview(tag, data, style);

2. Display Object 更新

推荐：

same objectId
+
updated public DTO
↓
upsertDisplayData

而不是：

remove everything
↓
rebuild all

3. Mesh Part 更新

单个 Part 变化：

viewer.upsertMeshPart(meshId, part);

无需业务层重新组织不相关 Part。

4. 完整 Mesh Transaction

需要先完成多个 Part 后再切换当前 Mesh：

beginMeshUpdate(meshId, true);
appendMeshPart(...);
appendMeshPart(...);
endMeshUpdate(meshId);

如果业务生成失败：

cancelMeshUpdate(meshId);

5. Preview Transform

Preview 几何没有变化时：

setPreviewTransform()

优于持续重新构建同一份 Preview Data。

6. Visibility & Style

只修改可见性或样式时优先调用：

setTargetVisible
setObjectsVisible
setTargetMaterialAppearance
setObjectsMaterialAppearance
setMeshPartStyle
setMeshPartsVisible

不要为了一个 Style 变化重新生成业务几何。

7. 业务状态是主状态

Viewer 是显示 SDK。

推荐业务系统维护自己的：

  • Geometry state；
  • visibility state；
  • material state；
  • selection-related business state。

Viewer API 用于同步显示，不应成为业务数据库的替代品。

商业 SDK 集成边界

1. 业务代码只依赖公开头

推荐：

#include <HtsViewerSdk.h>
HtsViewerSdk.h

不要引用：

hts.viewer/src/...
Viewer internal headers
OSG scene node headers for Viewer internals
internal Managers

2. 不依赖 Demo 私有模块

Viewer Demo 可能有：

  • CAD Importer；
  • UI Controller；
  • Product Demo model；
  • Authorization dialog。

这些是 Demo 应用，不是 Viewer SDK API。

业务项目需要 CAD Import 时，应接入自己的 CAD 数据链或单独采购/开发对应模块。

3. 不根据 Demo 推断 SDK 依赖

例如 Demo 为了加载 STEP 使用某个 CAD Kernel，并不表示 Viewer SDK 依赖该 Kernel。

SDK 依赖边界以正式：

include / lib / bin

发布内容和产品说明为准。

4. 不依赖私有行为

即使通过调试观察到 Viewer 当前版本的某些内部行为，也不要把它写进业务逻辑。

只有公开：

  • Header；
  • Manual；
  • Release Notes；

才构成 SDK 使用契约。

5. 避免泄露商业实现

对外技术材料可以介绍：

  • CAD/CAE 语义能力；
  • 增量接口；
  • 网格能力；
  • 交互能力；
  • 产品 Benchmark。

不应公开：

  • 内部合批策略；
  • 私有索引结构；
  • 内部渲染调度；
  • 缓存阈值；
  • Shader 实现；
  • 场景树组织细节；
  • 专利实现步骤超出公开专利文本的工程细节。
